# Code review, 2026-11-12 (server 0.13, agent 0.13.0)

A read of the engine, the server package and the endpoint agent for defects (not style), with every reported item
checked against the code before it was changed. Tests: `tests/unit/test_server_robustness.py`, additions to
`test_login_security`, `test_agent`, `test_agent_compaction`, `test_ebpf`, `test_installer_progress`; the isolation
rules were exercised in three containers on their own network (existing and new connections, server and elsewhere).

## Fixed - server

| # | Defect | Fix |
|---|---|---|
| S1 | **Two-factor bypass.** The 5-minute cookie issued after a correct password (`pdp_mfa`) was signed with the session key in the session format, and `access.session()` accepted it as a session for any user whose session generation was still 0: a password alone passed two-factor sign-in, and `/api/me/sessions/end` then issued a full session. | The pending cookie has its own signing domain (`mfa:`); `auth.read_session` refuses any payload marked `mfa`. |
| S2 | The notifier ran every organisation's round in one transaction: an error on one organisation's data rolled back every "sent" mark, so organisations before it were re-sent the same messages each round (the hourly limit's count rolled back too) and the ones after it got nothing. | One transaction per organisation's reading and per channel; failures are logged and counted. |
| S3 | `/api/overview` cast agent-supplied health values to bigint in SQL over every endpoint of the server: one endpoint's out-of-range value made the page fail for all organisations. | Query limited to the caller's endpoints, values read in Python; heartbeat numbers are bounded at intake. |
| S4 | Uploaded alert rows were stored unchecked; a context edge without `src`, a null score or a non-object reason raised in incident grouping, graphs, the allow list and the SIEM feed (which then stopped at that row for good). | `api.clean_alert` at upload; the feed coerces rows stored earlier. |
| S5 | The ingest-quota finding and security event were written and then rolled back by the 429. | The refusal is raised after the transaction commits. |
| S6 | A non-list `update.failed` in one heartbeat made `/status` fail for every endpoint of the organisation during a rollout. | `updates.clean_update` at intake; readers accept any stored shape. |
| S8 | A second ingest of a day already windowed (repeated `day-complete`, worker restart) recorded it with 0 events / 0 windows, so it no longer counted towards the baseline. | No second ingest job is queued while one is pending; an ingest that finds no raw events and a stored day keeps it. |
| S9 | A user limited to some endpoints saw the whole organisation in the weekly report and the names of all fleet members. | Both respect the reader's endpoint scope. |
| S10 | Deleting an endpoint or an organisation left `DATA_DIR/endpoints/<id>` (registry with every command line, path and address; window files) on disk. | Removed with the endpoint. A benchmark endpoint's store (a replayed public dataset the evaluation tools read by path) is kept. |
| S11 | A server-wide SSO sign-in re-enabled an account an administrator had disabled. | A disabled account is refused; losing access at the identity provider ends sessions through the session generation instead of the `disabled` flag. Accounts the old code disabled automatically stay disabled until an administrator enables them. |
| S12 | A database error while claiming or scheduling work ended the worker process. | Logged, retried; the failure handler's own writes are guarded. |
| S13 | A re-queued simulation campaign listed its earlier runs twice. | Runs are cleared when the job starts. |

## Fixed - agent 0.13.0

| # | Defect | Fix |
|---|---|---|
| A1 | **Isolation kept every established connection alive** (all three chains accepted `ct state established,related`), so a reverse shell or transfer open at the time went on. | Established traffic is accepted only from the server's addresses and ports; forwarding is dropped. An administrator's own SSH session to the host is cut too - the console's confirmation says so. |
| A2 | `kill_process` looked for the collector's process table on `source.procs`; the live sources keep it on `source.norm.procs`, so the pid-reuse check never ran. A program path containing a space was never stopped. | Both looked up; the label is compared with the full `/proc/<pid>/exe` path. |
| A3 | eBPF event times used a monotonic-to-wall offset measured once at start; after a suspend, a VM pause or a clock step every event was stamped that far off until restart. | Re-measured every 30 s, adopted when it moved by more than a second. |
| A4 | Registry compaction did not renumber the open window's rule hits: at window close they were attributed to whatever entity had moved into the old position. | Hits (and the unprocessed slice) are renumbered with the registry. |
| A7 | Every process exit scanned the whole fd-path table (up to 200 k entries). | Indexed by pid. |
| A8 | The ETW source reset its buffer after yielding it, discarding what the callback thread appended meanwhile. | Swapped before the yield. |
| A9 | A batch the server refuses as such (400 / 413 / 422) was retried for good and blocked every later alert. | Declared lost after 5 refusals (reported in the heartbeat). |
| A10 | A file error while unpacking or loading a new model counted as "offline": the model was already released, nothing was scored, and the bundle was downloaded again every interval. | Treated as a bad bundle: the current model is loaded again. |
| A12b | auditd: `openat2`'s third argument is a pointer, not flags; read/write was inferred from pointer bits. | Read, or write when the call created the file. |
| A13 | The scoring cursor could move backwards on a batch of late events and feed rows of the open window twice. | It only advances. |
| A14 | The installer's progress report put the single-use enrolment token on curl's command line every 3 s. | Sent on standard input. |
| A15 | The day-id cache kept an id whose row a rolled-back transaction had removed. | Cleared on rollback. |

## Not changed, and why

- **Layer-1 Windows paths with backslashes and spaces** (`backslash_paths`): clean lab test, rejected by its
  pre-registered rule (`artifacts/lab_v13`): 26 attacks kept, none gained, FP 1,051 -> 1,340.
- **Processes running before the agent started are `subject None None`** (A5) and layer 1 treats a missing program
  as known, so an implant already running when the agent (re)starts is exempt from layer 1. Reading `/proc/<pid>/exe`
  for them is easy, but every existing model was trained on those anonymous labels and its known-program list lacks
  daemons that never exec'd during the baseline: turned on for an existing endpoint it would raise a new-program
  alert for each long-running service. It needs a model refit and a field check, not a patch.
- **Confidentiality tags do not survive registry compaction** (engine `TagEngine.keep_nodes` keeps lowered integrity
  only): a process that read a credential store and then stays silent longer than `entity_max_age_h` (6 h) comes
  back as a new entity, and a later send to an untrusted address is not an exfiltration alarm. Keeping every
  confidentiality holder grows the registry without bound on hosts where every shell reads its history file; a
  bounded variant only moves the waiting time. Open design question.
- **Event-batch idempotency across the two databases** (S7): the duplicate check and the batch record are not atomic
  with the telemetry insert; a retry racing the first request stores the batch twice. Fixing it properly holds a
  platform connection for the whole upload; left until uploads are measured under that change.
- **auditd source**: re-reads the whole log on start and misses rotated files (A6), never forgets exited pids (A11),
  drops events when records of two serials interleave (A12a). The eBPF source is the default; these need a stateful
  rewrite of the follower and parser.
- Minor: `release()` records "released" even if `nft` fails; no SIGTERM handler saves entity ages; the bundle id is
  used as a path component before the signature is checked.
